# smart-mzcmc-commentator

解说端 —— **直播画面的包装层** + 给解说员看的大字提示。

解说员看的是芯象 PGM 画面，存在物理时延，而且导播不会提前告知下一步切什么。

这个应用干两件事，**同一条 WebSocket**：

1. 把导播的切台状态渲染成一张包装卡片，由采集端当**窗口源**抓走、作为画中画
   压进直播画面；
2. 同一张卡片也用超大字号显示预判指令，让解说能提前组织语言。

两件事能共用一份状态，是因为芯象**没法把输出画面和推流画面配成不一样**——包装层
必须真的进信号链，解说又必须看见它，两者只能是一份。

**C# / .NET 10 WPF** 桌面应用（`net10.0-windows`），无需登录，启动时读配置订阅项目。

## 界面

**两个窗口**。

### 播送标题窗口（无边框，就是卡片本身）

窗口**就是这张卡片**，不透明、不做成整屏浮层。采集端把它当窗口源抓走，再摆到输出
画面里设定的位置和大小上。

形制照 `tools/title-preview.png` **逐像素量出来**（`tools/measure_preview.py` 量、
`tools/verify_geometry.py` 核对，容差 0.6 设计单位）：灰底、顶部一条蓝条写赛事名，
蓝条**下方**是深色机位字，右端一块与蓝条**齐平**的竖条。

```
┌──────────────────────────────────────────┐
│ ████████████████████████████████████████ │
│ █               绵阳中学运动会           ██│
│ ████████████████████████████████████████ │
│ █  [正在播送]      20×50接力             █ │
└──────────────────────────────────────────┘
```

- 卡片是**阶梯状轮廓**，不是完整矩形。右端竖条与蓝条齐平（不是凸出的标签），
  竖条**下方**那 21.5 × 41.5 个单位**留空**；除此之外全是实体
- 这些留空在原始图形里是**透明**的。本窗口不能开 `AllowsTransparency`（见下），
  因此填成**色度抠像的键色**（`KeyColor`，默认纯绿 `#00FF00`），由采集端抠掉
- 因此**不需要画任何色块**：阶梯轮廓本身就是「哪些地方不画」构成的
- 卡片内部按 **310 × 87** 的设计单位算，实际像素 = 设计值 × u，u = 卡片宽 / 310。
  宽高比 **3.563:1**
- 卡片宽度 = **输出画面**宽度 × `CardWidthRatio`（默认 0.21）。按画面而不是按当前
  显示器定尺寸，换一台分辨率不同的机器做同一场直播时卡片不变样
- **有描边**，3 个设计单位（`#F2F5F7`），蓝条与灰底各自往内画。必须用 `Border` 的
  `BorderThickness` 而不是 `Rectangle` 的 `StrokeThickness`：后者以路径为中心，有
  一半落在卡片外面被窗口裁掉，实际只有 1.5 个单位，键色会镶一道边
- 机位名字号 20.9、赛事名 25.6，**不同号**（机位名略小）
- 无标题栏：**在空白处按住拖动可以挪窗口**，**右键**出菜单（置顶 / 鼠标穿透 / 显示状态窗口 / 退出）
- 默认置顶：解说员要对照副屏上的画面，置顶才压得住别的窗口
- **命中测试只有整块画布一个入口**，下面每一层都是 `IsHitTestVisible="False"` 的装饰件。
  右端竖条是紧贴卡片右边缘的（`288.5 + 21.5 = 310`，共 310），所以它看上去总是
  「被切掉一截」，那是设计如此，不是被裁

::: danger 不要给这个窗口加回 AllowsTransparency
`AllowsTransparency="True"` 会让 WPF 建 `WS_EX_LAYERED` 分层窗口，而分层窗口由 DWM
合成、**不往窗口 DC 里画**。采集软件用 `PrintWindow`（不带 `PW_RENDERFULLCONTENT`）
或从窗口 DC `BitBlt` 抓它，拿到的就是一片黑。

实测：解说端状态窗口（普通不透明窗口）采集正常，本窗口采到黑屏。所以窗口必须保持
不透明，透明区域一律靠**色度抠像**去实现——这正是 `KeyColor` 存在的原因。

采集端必须配成：键色 = `KeyColor`、相似度留足余量。

键色默认**纯绿 `#00FF00`**。不要换成看起来更「专业」的 EBU 绿 `#00B140`：卡片里现在
一点绿都没有（「正在播送」那块状态色已改成蓝 `#0F5588`），所以只剩「会不会把画面里的
绿也一起抠掉」这一个考量。纯绿饱和度 100%，而摄像机拍出来的绿永远带一点红蓝污染，
不会那么纯；`#00B140` 明度只有 35%，更贴近自然绿，键控容差得开更大才够用。纯绿也是
硬件键控器与剪辑软件支持最广的那个绿。

> ⚠ 现场如果已经跑过旧版，`config.json` 里会留着 `"KeyColor": "#FF00FF"`，
> **默认值覆盖不了它**（配置是反序列化进已有值的），需要自己改成 `#00FF00`。
>
> 如果连背景一起被抠掉了（运动会画面绿色遍地），把 `KeyColor` 改回 `#FF00FF` 即可，
> 洋红在体育直播里少见得多。

同理也别把窗口改成整屏大小——采集端既然能指定信号源在输出画面里的位置和大小，
窗口就只需要是卡片那么大：源更小、缩放更清晰，也不用再操心「整屏浮层挡住桌面」。
:::

::: tip 画面尺寸填物理像素，且必须 16:9
`CanvasWidth` / `CanvasHeight` 是**卡片的设计基准**，不是窗口尺寸。填物理像素，桌面
缩放 150% 时一张 403px 的卡片仍然是 403 个物理像素。非 16:9 的值会被忽略并退回
1920 × 1080——把宽高写反会得到一张明显偏小的卡片，播出前很难一眼看出来。
:::

- **摆位只认窗口当前所在的那块屏**：卡片摆在那块屏的右下角。之前用的是「主屏工作区 +
  系统 DPI」，混着不同缩放比例的显示器时会把窗口摆到两块屏的边界上，现场看到的就是
  标题条只剩一半。这个位置只影响本地观看，播出位置由采集端的画中画设置决定

**正在播送 / 即将播送的区分**（参考图本身不带状态，这是解说端独有的）：

| 状态 | 左下角小色块 | 含义 |
| :--- | :--- | :--- |
| 正在播送 | 蓝 `#0F5588` | 画面就是这台 |
| 即将播送 | 红 `#DC3737` | 导播已预切、还没切 |

主蓝条与右端竖条是**固定色**（`#0054B7` / `#0046A5`），不随状态变——变的是左下角那块
小色块，它写着「正在播送 / 即将播送」，是扫一眼之后的确认。冷暖对比（蓝 vs 红）比单纯
深浅差要好认得多。

在播色取参考图自己的 `#0F5588` 而**不是**蓝条的 `#0054B7`：同色时色块就不再像一块状态
标记，只剩下它的位置在说明「这里是状态」。

::: warning 「等待」状态已经删掉了
只有 `ShotState.HasPending` 一个布尔，即两态。之前还有个「等待」（灰 `#8A9099`），
`ShotState` 里已无对应字段，`ChipIdle` 只作为构造时的初值存在。文档与代码曾经长期
对不上，这里记一笔。
:::

赛事名启动时按 `ProjectId` 查一次 `GET /api/projects`。查不到就退回配置里的
`EventName`；两个都没有时**顶行整条隐藏**（右端竖条一起藏）——留一条空蓝条
会让人以为渲染坏了。

### 状态窗口（主屏上那个）

版本号、连接状态、内部消息流水、版本横幅。正文区是一列带时间戳的日志，
现场出问题时能直接看最近发生了什么，不用去翻控制台。

**右键**菜单里有一条「播送标题：鼠标穿透」，与标题窗口那一条是同一个开关——
卡片压在画面预览上、想让点击穿过去时用。

### 为什么要两个窗口

标题窗口要能搬到副屏上去，尺寸和主屏不一样。跟版本号挤在一个窗口里，副屏一
拉伸那些字也跟着变形；而版本横幅这类提示又不能没有——它是「必须让人知道」的
那类信息，不能静默。

早期版本把标题做成整屏透明浮层并自动开鼠标穿透，穿透之后它自己就点不到了，状态
窗口成了唯一逃生口。现在窗口收回到卡片大小、不再遮挡桌面，自动穿透也去掉了，但
两处入口都留着——现场临时要把卡片压在画面预览上时方便。

两个窗口共用**一条** WebSocket（`BroadcastSession`）。各开一条会导致两边状态
可能不一致——标题窗口显示「即将播送」而状态窗口显示「正在播送」，解说员无法
判断该信哪个，而这种矛盾在直播里是致命的。

## 切换动画

标题窗口在「正在播送 ↔ 即将播送」之间切换时，机位字会播一段动画。切换完全由
后端下发的 `shot_state` 驱动，本端不做任何推断。

四种样式都由 `config.json` 的 `Transition` 选：

| 值 | 效果 | 适合 |
| :--- | :--- | :--- |
| `slide`（默认） | 从下往上滑入 + 淡入 | 多数人，看着最像电视字幕条 |
| `fade` | 纯淡入淡出，不位移 | 对动效敏感的解说员 |
| `roll` | 横向推移，新内容把旧的顶出去 | 想要滚动字幕感 |
| `scale` | 沿垂直中线展开 + 淡入 | 想要明显的「弹开」感 |

时长上限 800ms 是硬约束：切台之间往往只隔几秒，旧内容在屏上留太久，解说员
会对着已经过时的机位名发呆。

导播按下「确认已切」时后端会再推一次**内容完全相同**的状态，界面会去重、
不重播动画——否则那一下看起来像是本机出了故障。

## 配置


`config.json`（随构建复制到输出目录，**运行期读取，改完重启 exe 即可生效，不需要重新编译**）：

```json
{
  "ServerUrl": "http://zhdb.647382.xyz",
  "WsUrl": "ws://zhdb.647382.xyz/ws",
  "ProjectId": 1,
  "Role": "commentator",
  "Username": "",
  "Password": "",
  "EventName": "",
  "CanvasWidth": 1920,
  "CanvasHeight": 1080,
  "CardWidthRatio": 0.21,
  "MarginBottomRatio": 0.06,
  "MarginRightRatio": 0.04,
  "Transition": "slide",
  "TransitionMs": 300,
  "ProgOffsetX": -25
}
```

| 字段 | 说明 |
| :--- | :--- |
| `WsUrl` | **实际生效**的地址。反代部署下是 `ws://<域名>/ws` |
| `ProjectId` | 目标项目 id。也用来查顶行的赛事名 |
| `Role` | 固定 `commentator` |
| `ServerUrl` | HTTP 接口地址，**登录与查项目名时用** |
| `Username` / `Password` | 登录账号。**留空表示不登录** |
| `EventName` | 赛事名**兜底值**，留空即可。填了也不优先于服务端 |
| `CanvasWidth` / `CanvasHeight` | 输出画面尺寸（卡片的设计基准），**物理像素**，默认 1920 × 1080。**必须 16:9**，不是就退回默认值 |
| `CardWidthRatio` | 卡片宽度占**输出画面**宽度的比例，夹在 0.05..0.60 |
| `MarginBottomRatio` / `MarginRightRatio` | 卡片下 / 右边缘到**屏幕**边缘的比例。只影响本地位置，播出位置由采集端决定 |
| `KeyColor` | 色度抠像的键色，卡片留空处填这个色，默认 `#00FF00` 纯绿。**老配置文件不会被默认值覆盖，改完记得核对这一行** |
| `Transition` | 切换动画样式，见下表。**认不出来的值按 `slide` 处理** |
| `TransitionMs` | 动画时长毫秒数。`0` 关闭动画，超过 `800` 压回 `800` |
| `ProgOffsetX` | 机位名水平偏移（设计单位），负数向左 |

### 关于登录账号

解说端此前在服务端是**匿名的**：任何人知道那个地址就能监听整个项目的实时
消息。后端把 `REQUIRE_PROJECT_MEMBERSHIP` 打开之后，WebSocket 会校验「这个
账号是不是该项目的成员」，没有令牌的连接会在握手阶段被拒。

**账号留空时不登录，行为与改动前完全一致**，所以可以先把配置发下去、确认
现场都没受影响，再打开后端的开关。

- 每次重连都会**重新登录**：JWT 默认 60 分钟过期，长时间运行的客户端拿旧
  令牌重连会一直失败。
- 登录失败会显示在底部状态栏（`[系统] 登录失败 HTTP 401：...`），
  不会只停在「连接中...」——现场能直接看出是账号问题还是网络问题。
- 开启 HTTPS 后 `ServerUrl` 也要跟着改成 `https://`。

::: danger 启用 HTTPS 后必须把 `ws://` 改成 `wss://`
原生应用不受「混合内容」限制，但服务端若只在 443 提供 TLS，`ws://` 仍然连不上。
:::

::: tip 反代与直连的区别
- **直连**（本地开发）：`ws://<服务器IP>:3002/ws`，`ServerUrl` 同理带 `:3000`
- **反代**（生产）：`ws://<域名>/ws`，nginx 把 `/ws` 转到 3002

两种形态都由后端首页自动识别并显示，配置照着首页「接入地址」区块填即可。
:::

## 通信

只接收，不发送业务指令。处理的消息类型：

| type | 行为 |
| :--- | :--- |
| `shot_state` | 读 `payload.current` / `payload.next`：`next` 非空显示「即将播送：」，否则显示「正在播送：」 |
| `chat` | 内部消息，显示在底部状态栏 |
| `system` | 系统提示；**连接成功的那条带 `current_shot`**，据此在连上的一瞬间就渲染当前状态 |

连接后周期性发送心跳（`chat` + `payload.message = "heartbeat"` + `ts`）保活。
后端在入库前就会丢弃心跳，所以它不会进日志、也不计入消息统计；`ts` 供服务端
刷新「最后一次见到这个客户端」的时刻，掉线扫描判断的就是它。断线自动重连。

::: tip 中途连上也看得到当前状态
后端在握手时的欢迎消息里带上项目当前的切台状态，所以**重连或中途启动的解说端
不必等下一次切台**就能显示正确的画面。在此之前它会一直停在「等待导播指令」，
而这中间的解说内容已经和画面脱节了。
:::

## 部署

发布后把 `publish/` 整个目录（含 `config.json`）拷到解说员机器上，双击 exe 即可。
改服务器地址直接编辑 `config.json`，无需重新编译。

启动后会开两个窗口：状态窗口留在主屏，播送标题窗口默认置顶、居中摆在它所在那块屏上。
卡片在画面里的右下角，**位置不用调**——它要被芯象当窗口源抓走，窗口在屏幕上摆哪儿
都不影响播出结果。

### 接进芯象

1. 芯象里新增一个信号源，类型选**窗口**，选中标题是「播送标题」的那个窗口
   （无边框、卡片大小；另一个「解说端状态」是操作台，别选错）。
2. 给这个源打开**色度抠像**，键色填 `config.json` 里的 `KeyColor`（默认 `#00FF00`
   纯绿），相似度留足余量。卡片是阶梯状轮廓，竖条下方那一块是这个色。
3. 把这个源作为**画中画**压到 PGM 输出上，位置与大小按包装惯例设：横向靠右、
   纵向在下三分之一附近。采集端若只能「铺满整帧」，别用它——卡片是 3.56:1 的窄条，
   铺满会被拉伸变形。
4. 采集端的输出分辨率填和 `CanvasWidth` × `CanvasHeight` 一致的 16:9（默认 1920 × 1080），
   这样卡片缩放后的字号与设计值一致。

窗口是 `NoResize` 的，尺寸只能改 `config.json` 后重启。想让卡片更大就调
`CardWidthRatio`（默认 0.21，可到 0.60）；字号、条宽、缝隙全是按卡片尺寸的比例算的，
从 720p 到 4K 都不用改别的配置。

### 关闭

**关掉状态窗口就是退出整个解说端，播送标题窗口跟着一起关。**

单独关掉播送标题窗口不会退出：状态窗口会重新显示出来，WebSocket 照常接着，
现场要「把包装层撤下来、留着查日志」时仍然可用。真要退出就在任何一个窗口上
走「退出解说端」。

::: danger 不要把 ShutdownMode 改回 OnExplicitShutdown
那个模式下关掉状态窗口后进程还活着，副屏上那块标题窗口继续跑，操作台却已经
没了——想退出只能跑到副屏上对着标题窗口右键，现场表现是「关掉了却好像没关
干净，重开一个又变成两个」。
:::
