# smart-mzcmc-commentator

解说端 —— **直播画面的包装层** + 给解说员看的大字提示。

解说员看的是芯象 PGM 画面，存在物理时延，而且导播不会提前告知下一步切什么。

这个应用干两件事，**同一条 WebSocket**：

1. 把导播的切台状态渲染成一条 16:9 的包装层（下三分之一字幕条），由芯象当**窗口源**
   抓走、叠进直播画面；
2. 同一块画面也用超大字号显示预判指令，让解说能提前组织语言。

两件事能共用一份状态，是因为芯象**没法把输出画面和推流画面配成不一样**——包装层
必须真的进信号链，解说又必须看见它，两者只能是一份。

**C# / .NET 10 WPF** 桌面应用（`net10.0-windows`），无需登录，启动时读配置订阅项目。

## 界面

**两个窗口**。

### 播送标题窗口（无边框，16:9 画布）

**窗口本身就是一张 16:9 画面**（默认 1920 × 1080），卡片摆在画面里的下三分之一靠右，
其余部分透明。芯象把它当窗口源抓走，就是一张干净的叠加层——窗口在屏幕上摆哪儿都不
影响播出结果，也不需要跟采集区域对齐。

形制照 `tools/reference.png`（逐像素量出来的比例）：灰底、顶部一条带浅色描边的
蓝条写赛事名，蓝条**下方**是深色机位字，右端一条几乎同高的竖条。

```
┌──────────────────────────────────────────┐
│                                          │
│                                          │
│                                          │
│   ┌──────────────────────────────────┐ █  │
│   │      绵阳中学运动会              │ █  │
│   └──────────────────────────────────┘ █  │
│   [即将播送]         跳长绳               │
└──────────────────────────────────────────┘
```

- 卡片内部按 310 × 87 的设计单位算（灰底 290 × 87 + 右端竖条 21），蓝条占卡片宽
  92.9%、高 51.7%；实际像素 = 设计值 × u，u = 卡片宽 / 310
- 卡片宽度 = 画面宽度 × `CardWidthRatio`（默认 0.21，央视下三分之一字幕条的量）
- 蓝条外缘有一圈浅色描边 `#A0B4C8`——少了它蓝条像贴上去的色块
- 字号按「文字长度 × 可用宽度」算，超长才缩小
- 无边框所以没有标题栏：**在空白处按住拖动可以挪窗口**，**右键**出菜单（置顶 / 鼠标穿透 / 显示状态窗口 / 退出）
- 默认置顶：解说员要对照副屏上的画面，置顶才压得住别的窗口
- **命中测试只有整块画布一个入口**，下面每一层都是 `IsHitTestVisible="False"` 的装饰件。
  右端竖条是紧贴卡片右边缘的（`288.5 + 21 = 309.5`，共 310），所以它看上去总是
  「被切掉一截」，那是设计如此，不是被裁

::: danger 画布必须是 16:9
窗口源是按采集端的**输出画面比例**缩放的。比例不是 16:9 就是变形或者裁边，而这种错
在播出前很难一眼看出来，所以 `CanvasWidth` / `CanvasHeight` 里填了非 16:9 的值会被
**忽略并退回 1920 × 1080**。

不要试图让窗口本身变成 3.56:1 的窄条来「省掉黑边」——窄条被塞进 16:9 只能裁两侧，
先被吃掉的就是右端竖条。16:9 的下三分之一包装本来就该是一张 16:9 画面。
:::

::: warning 铺满屏幕时会自动开鼠标穿透，穿透之后右键菜单就出不来了
1920 × 1080 的画布在 1080p 桌面上会盖住整块屏，不穿透的话操作员连桌面都点不进去，
所以铺满时自动打开穿透。

而穿透之后这个窗口自己就接收不到右键了。**关掉穿透要去状态窗口**（主屏那个 maximization
窗口）右键 → 「播送标题：鼠标穿透」。
:::

- **摆位只认窗口当前所在的那块屏**：画布居中摆在那块屏上，尺寸按那块屏的工作区算。
  之前用的是「主屏工作区 + 系统 DPI」，混着不同缩放比例的显示器时会把窗口摆到两块屏的
  边界上，现场看到的就是标题条只剩一半

**正在播送 / 即将播送的区分**（参考图本身不带状态，这是解说端独有的）：

| 状态 | 主蓝条 + 右端竖条 | 小色块 | 含义 |
| :--- | :--- | :--- | :--- |
| 正在播送 | 参考图原色 `#0F5588` / `#004885` | 绿 `#4ECCA3` | 画面就是这台 |
| 即将播送 | 琥珀 `#B8860B` / `#8A6408` | 琥珀 `#D9A441` | 导播已预切、还没切 |
| 等待 | 中性灰 `#5A5F6B` / `#3A3F4B` | 灰 `#3A3F4B` | 还没收到指令 |

主蓝条整条变色是最大信号，余光就能读到；左下角小色块写着「正在 / 即将 / 等待」，
是扫一眼之后的二次确认。冷暖对比（蓝 vs 琥珀）比单纯深浅差要好认得多。

赛事名启动时按 `ProjectId` 查一次 `GET /api/projects`。查不到就退回配置里的
`EventName`；两个都没有时**顶行整条隐藏**（右端竖条一起藏）——留一条空蓝条
会让人以为渲染坏了。

### 状态窗口（主屏上那个）

版本号、连接状态、内部消息流水、版本横幅。正文区是一列带时间戳的日志，
现场出问题时能直接看最近发生了什么，不用去翻控制台。

**右键**菜单里有一条「播送标题：鼠标穿透」——播送标题铺满屏幕并自动穿透之后，
它自己就点不到了，这里是唯一的逃生口。

### 为什么要两个窗口

标题窗口要整块搬到副屏上，尺寸和主屏不一样。跟版本号挤在一个窗口里，副屏一
拉伸那些字也跟着变形；而版本横幅这类提示又不能没有——它是「必须让人知道」的
那类信息，不能静默。

标题窗口铺满屏幕并自动开了鼠标穿透之后，状态窗口还是唯一能点到的窗口，所以
「关掉穿透」这条入口必须留在这里。

两个窗口共用**一条** WebSocket（`BroadcastSession`）。各开一条会导致两边状态
可能不一致——标题窗口显示「即将播送」而状态窗口显示「正在播送」，解说员无法
判断该信哪个，而这种矛盾在直播里是致命的。

## 切换动画

标题窗口在「正在播送 ↔ 即将播送」之间切换时，机位字会播一段动画。切换完全由
后端下发的 `shot_state` 驱动，本端不做任何推断。

四种样式都由 `config.json` 的 `Transition` 选：

| 值 | 效果 | 适合 |
| :--- | :--- | :--- |
| `slide`（默认） | 从下往上滑入 + 淡入 | 多数人，看着最像电视字幕条 |
| `fade` | 纯淡入淡出，不位移 | 对动效敏感的解说员 |
| `roll` | 横向推移，新内容把旧的顶出去 | 想要滚动字幕感 |
| `scale` | 沿垂直中线展开 + 淡入 | 想要明显的「弹开」感 |

时长上限 800ms 是硬约束：切台之间往往只隔几秒，旧内容在屏上留太久，解说员
会对着已经过时的机位名发呆。

导播按下「确认已切」时后端会再推一次**内容完全相同**的状态，界面会去重、
不重播动画——否则那一下看起来像是本机出了故障。

## 配置


`config.json`（随构建复制到输出目录，**运行期读取，改完重启 exe 即可生效，不需要重新编译**）：

```json
{
  "ServerUrl": "http://zhdb.647382.xyz",
  "WsUrl": "ws://zhdb.647382.xyz/ws",
  "ProjectId": 1,
  "Role": "commentator",
  "Username": "",
  "Password": "",
  "EventName": "",
  "CanvasWidth": 1920,
  "CanvasHeight": 1080,
  "CardWidthRatio": 0.21,
  "MarginBottomRatio": 0.06,
  "MarginRightRatio": 0.04,
  "Transition": "slide",
  "TransitionMs": 300,
  "ProgOffsetX": -25
}
```

| 字段 | 说明 |
| :--- | :--- |
| `WsUrl` | **实际生效**的地址。反代部署下是 `ws://<域名>/ws` |
| `ProjectId` | 目标项目 id。也用来查顶行的赛事名 |
| `Role` | 固定 `commentator` |
| `ServerUrl` | HTTP 接口地址，**登录与查项目名时用** |
| `Username` / `Password` | 登录账号。**留空表示不登录** |
| `EventName` | 赛事名**兜底值**，留空即可。填了也不优先于服务端 |
| `CanvasWidth` / `CanvasHeight` | 包装画布尺寸，**物理像素**，默认 1920 × 1080。**必须 16:9**，不是就退回默认值 |
| `CardWidthRatio` | 卡片宽度占**画面**宽度的比例，夹在 0.05..0.60 |
| `MarginBottomRatio` / `MarginRightRatio` | 卡片下边缘 / 右边缘到画面边缘的比例 |
| `Transition` | 切换动画样式，见下表。**认不出来的值按 `slide` 处理** |
| `TransitionMs` | 动画时长毫秒数。`0` 关闭动画，超过 `800` 压回 `800` |
| `ProgOffsetX` | 机位名水平偏移（设计单位），负数向左 |

### 关于登录账号

解说端此前在服务端是**匿名的**：任何人知道那个地址就能监听整个项目的实时
消息。后端把 `REQUIRE_PROJECT_MEMBERSHIP` 打开之后，WebSocket 会校验「这个
账号是不是该项目的成员」，没有令牌的连接会在握手阶段被拒。

**账号留空时不登录，行为与改动前完全一致**，所以可以先把配置发下去、确认
现场都没受影响，再打开后端的开关。

- 每次重连都会**重新登录**：JWT 默认 60 分钟过期，长时间运行的客户端拿旧
  令牌重连会一直失败。
- 登录失败会显示在底部状态栏（`[系统] 登录失败 HTTP 401：...`），
  不会只停在「连接中...」——现场能直接看出是账号问题还是网络问题。
- 开启 HTTPS 后 `ServerUrl` 也要跟着改成 `https://`。

::: danger 启用 HTTPS 后必须把 `ws://` 改成 `wss://`
原生应用不受「混合内容」限制，但服务端若只在 443 提供 TLS，`ws://` 仍然连不上。
:::

::: tip 反代与直连的区别
- **直连**（本地开发）：`ws://<服务器IP>:3002/ws`，`ServerUrl` 同理带 `:3000`
- **反代**（生产）：`ws://<域名>/ws`，nginx 把 `/ws` 转到 3002

两种形态都由后端首页自动识别并显示，配置照着首页「接入地址」区块填即可。
:::

## 构建与运行

需要 **.NET 10 SDK**（Windows）。

```bash
dotnet restore
dotnet build --configuration Release
dotnet run                        # 直接运行

dotnet publish --configuration Release --output publish
```

## 通信

只接收，不发送业务指令。处理的消息类型：

| type | 行为 |
| :--- | :--- |
| `shot_state` | 读 `payload.current` / `payload.next`：`next` 非空显示「即将播送：」，否则显示「正在播送：」 |
| `chat` | 内部消息，显示在底部状态栏 |
| `system` | 系统提示；**连接成功的那条带 `current_shot`**，据此在连上的一瞬间就渲染当前状态 |

连接后周期性发送心跳（`chat` + `payload.message = "heartbeat"` + `ts`）保活。
后端在入库前就会丢弃心跳，所以它不会进日志、也不计入消息统计；`ts` 供服务端
刷新「最后一次见到这个客户端」的时刻，掉线扫描判断的就是它。断线自动重连。

::: tip 中途连上也看得到当前状态
后端在握手时的欢迎消息里带上项目当前的切台状态，所以**重连或中途启动的解说端
不必等下一次切台**就能显示正确的画面。在此之前它会一直停在「等待导播指令」，
而这中间的解说内容已经和画面脱节了。
:::

## 部署

发布后把 `publish/` 整个目录（含 `config.json`）拷到解说员机器上，双击 exe 即可。
改服务器地址直接编辑 `config.json`，无需重新编译。

启动后会开两个窗口：状态窗口留在主屏，播送标题窗口默认置顶、居中摆在它所在那块屏上。
卡片在画面里的右下角，**位置不用调**——它要被芯象当窗口源抓走，窗口在屏幕上摆哪儿
都不影响播出结果。

### 接进芯象

1. 芯象里新增一个信号源，类型选**窗口**，选中 `CommentatorApp.exe` 的主窗口
   （无边框那个，标题是「播送标题」）。
2. 采集/输出分辨率设成和 `CanvasWidth` × `CanvasHeight` 一致的 16:9（默认 1920 × 1080）。
   两边不一致就是缩放，成比例不会变形，但字号会跟设计值有偏差。
3. 把这个源作为叠加层压到 PGM 输出上，透明度保持 100%（卡片区域不透明，其余透明）。

::: warning 抓不到透明区域就是抓成了纯黑
本窗口是 WPF 的分层窗口（`AllowsTransparency`）。绝大多数采集软件走 DXGI 桌面复制，
能正常抓到透明区域；如果抓出来整块是黑的，说明它用的是 `PrintWindow` 且没带
`PW_RENDERFULLCONTENT`。换一种抓取方式，或者把窗口改成不透明 + 采集端做色度抠像。
:::

窗口是 `NoResize` 的，尺寸只能改 `config.json` 后重启。想让卡片更大就调
`CardWidthRatio`（默认 0.21，可到 0.60）；字号、条宽、缝隙全是按卡片尺寸的比例算的，
从 720p 到 4K 都不用改别的配置。

### 关闭

**关掉状态窗口就是退出整个解说端，播送标题窗口跟着一起关。**

单独关掉播送标题窗口不会退出：状态窗口会重新显示出来，WebSocket 照常接着，
现场要「把包装层撤下来、留着查日志」时仍然可用。真要退出就在任何一个窗口上
走「退出解说端」。

::: danger 不要把 ShutdownMode 改回 OnExplicitShutdown
那个模式下关掉状态窗口后进程还活着，副屏上那块标题窗口继续跑，操作台却已经
没了——想退出只能跑到副屏上对着标题窗口右键，现场表现是「关掉了却好像没关
干净，重开一个又变成两个」。
:::
